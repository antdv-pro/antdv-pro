# 运输管理财务月统计卡片

## 目标

运输管理下所有模块的顶部统计卡片使用一致的财务月口径，帮助调度、财务和管理人员直接识别本月业务量、金额和待处理事项相对上月的变化。

## 财务月口径

- 当前财务月：上月 26 日（含）至本月 25 日（含）。
- 接口查询使用左闭右开区间，即开始日 00:00（含）至结束日 00:00（不含）。
- 页面首次进入默认当前财务月；用户明确选择其它财务月时，卡片比较所选财务月与其上一个财务月。
- 卡片主值是当前财务月数据，底部统一显示 `上月具体值 · 上升/下降/持平百分比`。
- 上月为 0 且本月大于 0 时显示“本月新增”，不计算无穷百分比；两个月均为 0 时显示“持平 0%”。

## 模块指标

| 模块 | 当前财务月核心指标 |
| --- | --- |
| 运营数据 | 运营车辆、订单、总运费、税后运费、总成本、总利润、审批通过金额、已使用金额 |
| 运输订单 | 订单数、运费总额、税后运费、待审核订单 |
| 北斗监控 | 报警数、已处理报警、未处理报警、涉及车辆 |
| 加油明细 | 加油记录、燃油支出、涉及车辆、平均单笔 |
| ETC 费用 | 通行笔数、ETC 费用、涉及车辆、待处理记录 |
| 规费管理 | 生效规费、财务月费用、审批金额、已使用金额 |
| 维保管理 | 维保记录、维保费用、审批金额、使用金额、待审核记录、推修中车辆 |
| 司机薪酬 | 出勤天数、运输趟次、待核算/审批、实发合计 |
| 车贷费用 | 应还合同、应还金额、已还金额、逾期期数 |
| 账单核对 | 系统运单、系统运费、客户账单、核对差异 |
| 基础数据 | 当前档案页签的记录、异常/待处理、可识别金额、业务类型数，按档案更新时间归属财务月 |

北斗监控的实时在线/离线状态属于即时快照，没有可比的月度历史快照，因此不用于财务月环比。账单核对的客户账单和差异数从上月归档读取；未归档时上月值按 0 展示。

## ETC 实际路线分析

ETC 页面使用一个合并后的路线费用排行：数据按实际路线分析结果汇总，视觉沿用原收费站组合排行的双列横条形式，显示当前筛选范围金额前 8 项。每行主名称是基础资料中的业务路线，金额和笔数仍来自其包含的 ETC 原始明细；路线编号、里程、置信度、估算行程和收费站组合放在路线名称的悬浮信息中。

实际路线匹配优先级如下：

1. 同车牌、同日期只有一条有效运输订单时，采用订单路线并匹配基础路线。
2. ETC 明细已保存业务路线时，按路线端点匹配基础路线。
3. 收费站端点可唯一命中基础路线时，采用该路线。
4. 同一无向收费走廊已有至少 2 条核对样本，且同一路线占比不低于 80% 时，对剩余记录标记为“推断”。
5. 无法唯一判断时进入“待确定路线”，提示“待录入同车同日订单后自动查验”，禁止强制归类。

路线分析是查询时动态计算，不把匹配结论写死到 ETC 明细。后续补录运输订单后，再次进入页面或执行查询会按车牌和通行日期读取最新订单：同车同日只有一条有效路线时自动转为“已核对”；存在多条不同路线或仍无法对应基础路线时继续保持“待确定”。订单路线发生修改或删除时，下一次查询也会按最新数据重新判断。

页面中的“ETC 明细”是发票/通行记录笔数，不是运输趟次。“估算行程”优先使用导入时生成的行程标识；历史数据没有行程标识时，按车牌、日期和实际路线去重。因此估算行程只用于分析，不替代运单趟次口径。

## 验收清单

- 25 日和 26 日数据分别归入正确财务月，1 月跨年比较正确。
- 数量显示明确单位，金额使用人民币千分位格式。
- 上升、下降、持平和本月新增文案与计算结果一致。
- 上月为 0、负利润、无数据和接口加载状态不产生 `Infinity`、`NaN` 或布局跳动。
- 桌面端四列卡片和移动端单列卡片不截断上月值及变化比例。
- 筛选条件中的车牌、司机、状态等业务条件同时应用于本月和上月，保证对比范围一致。
- ETC 路线费用排行显示“笔”而不是“趟”，数据来源为实际路线归并结果；无法唯一识别时显示“待确定路线”，不静默归入相似路线。
- ETC 明细未命中订单时显示“待确定”；补录唯一的同车同日订单后重新查询，应自动归入订单对应的基础路线并显示“已核对”。
