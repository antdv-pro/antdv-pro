# 酒店流水与房态管理

## 财务月报表口径

- 财务月沿用系统统一规则：每月 26 日至次月 25 日，展示标签按财务年/月显示，不按自然月切分。
- 收入、支出、利润、支付方式净额及趋势图均按所选财务年月汇总；可选择另一财务年月进行对比。
- 报表统计截止当前日期前一天（`昨天`），当天录入的数据不会进入月度指标、趋势或导出文件。营业日明细和录入流程仍可使用当天日期。
- “导出经营日报”现导出已完成财务日的月度汇总，包含财务年月、统计起止日期、收入、支出、利润和流水笔数。

## 录入规则

- 新增流水支持同一营业日一次录入多笔收入和支出；每笔均需填写类型、分类、金额、支付方式和经手人。
- 编辑既有流水保持单笔模式，避免误改同日的其他账项。
- 同一批提交只保存一次当日房态。房态包含总房间数、入住房间数及备注；入住房间数必须介于 `0` 与总房间数之间。
- 保存采用增量 `upsert` 和按 ID 删除，不会覆盖同日未提交的其他流水。

## 权限和数据范围

- 读取和变更接口仅允许 `ADMIN` 与 `FINANCE_MANAGER`。
- 酒店流水按当前登录用户的 `companyId` 查询和写入。公司标识由服务端从登录上下文取得，客户端不得传入或伪造。
- 删除使用软删除，审计日志和流水修订记录保留创建、更新及删除动作。

## 数据库迁移

生产库依次执行 `deploy/mysql/migrations/20260804_001_hotel_revenue_company.sql` 与 `deploy/mysql/migrations/20260804_002_hotel_daily_company.sql` 后，流水和房态都会按公司隔离。前者为 `hotel_revenue` 增加 `company_id` 与 `(company_id, revenue_date)` 索引；后者将房态主键调整为 `(company_id, business_date)`，支持不同公司记录同一营业日。迁移会检测已有结构，可重复执行。

发布后应按以下闭环验收：新建至少一笔收入和一笔支出，刷新页面确认仍可读取，删除验收记录后再次刷新确认其不再出现。验收记录应使用明确的唯一备注，并在测试结束后清理。
