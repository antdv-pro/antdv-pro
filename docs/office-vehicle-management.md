# 办公用车汇总与录入规范

## 产品目标

办公用车页面以车辆为管理主线，减少行政人员在车辆、费用、证照和保险之间反复切换、重复选择车辆的操作。

成功标准：

- 汇总表一行对应一辆办公用车，可直接判断费用规模和近期风险。
- 新建车辆时，可在同一个弹窗内录入多条费用、证照和保险。
- 证照与保险只维护业务记录本身；到期日自动进入首页统一到期预警，不再重复录入独立到期事项。
- 任一关联记录校验或保存失败时，本次整车资料均不落库。
- 已有费用审批、记录权限、单条编辑和删除规则保持不变。

## 信息架构

### 车辆汇总表

车辆是表格的唯一行粒度，固定展示以下信息：

| 列 | 内容 | 交互 |
| --- | --- | --- |
| 车辆 | 车牌号、品牌型号、车辆类型 | 点击车牌打开车辆详情抽屉 |
| 归属信息 | 所属部门、负责人 | 无 |
| 本月费用 | 当前财务期间费用合计、记录数 | 详情抽屉查看全部费用 |
| 证照 | 最近到期证照、状态、到期日、数量 | 详情抽屉查看和维护 |
| 保险 | 最近到期保险、状态、到期日、数量 | 详情抽屉查看和维护 |
| 车辆状态 | 正常、停用、维修中或已出售 | 无 |
| 操作 | 查看、补充资料、编辑、删除 | 使用服务端权限控制 |

费用类型、证照类型、保险类型和状态筛选仍然保留，但筛选结果返回匹配的车辆，而不是拆散后的业务记录。

### 车辆详情抽屉

详情使用侧边抽屉，避免与单条编辑弹窗叠加。抽屉内按费用、证照、保险和日志分区；关联记录仍可执行原有编辑、审核和删除操作。

## 统一录入流程

“新增整车资料”弹窗包含四个连续区段：

1. 车辆信息：车牌号和品牌型号必填。
2. 费用记录：可选，可添加多条，每条独立填写类型、金额、日期、支付和票据信息。
3. 证照资料：可选，可添加多条，每条独立填写编号、有效期和附件。
4. 保险信息：可选，可添加多条，每条独立填写保单、保费、保险公司和有效期。

“补充资料”复用同一弹窗，并以当前车辆为上下文。用户不需要在每条关联记录中重复选择车辆。

## 数据与事务

聚合接口：

```text
POST /api/office-vehicle/batch-save
```

请求结构：

```ts
{
  vehicle: Partial<OfficeVehicle>
  expenses: Array<Partial<OfficeVehicleExpense>>
  licenses: Array<Partial<OfficeVehicleLicense>>
  insurances: Array<Partial<OfficeVehicleInsurance>>
  // 历史兼容字段 reminders 服务端仍可接收，新页面不再提交。
  reminders?: Array<Partial<OfficeVehicleReminder>>
}
```

服务端先加载一次办公用车状态，按车辆、费用、证照、保险的顺序执行现有业务校验，全部成功后只持久化一次。MySQL 使用事务写入全部结构化表；本地 JSON 模式也只执行一次写入。任一子项失败时恢复保存前的内存快照，并返回包含类别和序号的错误，例如“费用第 2 条：费用金额必须为有效的非负数”。历史提醒数据保留用于审计和回滚，但不再进入新页面信息架构。

## 权限规则

- 整车新增和补充资料要求 `ADMIN` 或 `OFFICE_ADMIN`，因为请求包含车辆档案维护。
- 费用单条维护继续允许 `FINANCE_MANAGER`，不改变既有财务工作流。
- 证照、保险和车辆档案继续使用办公车辆管理员权限。

## 首页到期预警

首页通过 `/api/dashboard/expiry-warnings` 读取统一预警数据，并按“证照、保险、年检、规费、车贷、应收应付”分类展示。来源包括：

- 办公用车证照的到期日期。
- 办公用车保险的结束日期。
- 运输规费的有效期截止日期，并按业务名称归入证照、保险、年检或其他规费。
- 运输基础资料车辆的保险到期日和年检到期日。
- 运输车贷的下一期未还款日期。
- 应收应付中尚未结清单据的到期日期；仅向具备财务或审批角色的用户返回。

展示范围包含所有已过期记录及未来 30 天内到期记录。同一对象、同一业务类型存在多次续期记录时，只采用到期日最新的一条；首页明细可跳回原业务模块。车贷和应收应付保持独立分类，不混入证照有效期预警。
- 费用审批状态与金额以服务端返回为准，页面不做乐观更新。

## 验证要求

- 服务端测试覆盖多条关联记录成功保存、只持久化一次和任一子项失败时整体回滚。
- API 合约测试覆盖聚合接口路径和请求体。
- 前端通过 TypeScript 类型检查和生产构建。
- 桌面端验证汇总列可扫描、固定操作列可用；窄屏验证横向滚动、弹窗纵向滚动和表单字段不重叠。
