# 审批中心概览与统计口径

## 产品目标

审批中心顶部同时提供个人工作量概览和业务部门金额概览，帮助审批人先判断待办规模，再识别待审批资金集中在哪些业务部门。

成功标准：

- 保留“待我审批、我发起的、已审批、待审批金额”四项工作台指标。
- 按业务所属部门分别显示待审批金额及待审笔数。
- 卡片金额与当前财务期间、状态和关键字筛选结果保持一致。
- 缺失部门或历史金额字段不会导致审批单从统计中消失。

## 顶部信息结构

顶部卡片区按以下顺序展示：

1. 工作台概览：展示个人待办、本人发起、已处理任务和筛选范围内的待审批总金额。
2. 各业务部门待审批金额：每个业务部门一张卡片，展示金额合计和待审笔数。
3. 审批洞察：沿用现有审批状态和处理效率分析。

部门金额卡片使用与现有概览卡相同的视觉和响应式规则；桌面端每行最多四张，窄屏自动换行。

## 统计口径

- 数据范围：审批实例接口按当前财务年度、财务月份或自定义日期范围返回的数据，再应用页面状态和关键字筛选。
- 待审批状态：仅包含 `PENDING` 和 `APPROVING`。
- 部门：优先使用审批实例的 `deptName`，兼容历史快照中的 `departmentName`；无有效部门时归入“未分配部门”。
- 金额：依次兼容审批实例的 `amount`、`formSnapshot.amount`、`payload.amount` 和历史 `formData.amount`，仅汇总有效数值。
- 排序：部门卡片按待审批金额从高到低排列；金额相同时按中文部门名排序。
- 无数据：当前筛选范围内没有待审批单时，部门区域显示统一空态。

## 权限与数据边界

本功能不新增接口、权限或持久化字段。用户能够看到的部门金额完全来自审批实例列表接口的现有权限结果，不在前端扩大数据范围。

审批实例接口当前返回筛选范围内的完整集合，不存在只汇总当前分页的问题。后续若该接口改为分页，部门金额应迁移到服务端聚合接口，不能继续由当前页数据推算。

## 审批详情展示口径

- 审批节点按实际审批人展示，人员名称、个人状态、操作时间和审批意见来自审批详情快照或本地审批任务。
- 企业微信来源单据以 `formSnapshot.approvalFlow` 为展示事实来源；即使本地存在“管理员审批”等模板占位节点，也不得覆盖企业微信返回的实际审批人。
- 每次企业微信状态同步必须同时刷新审批人流程快照，避免总状态与人员状态来自不同同步时点。
- 本地发起的审批按节点分组，并通过 `nodeId` 关联审批任务展示人员；尚未生成任务的后续节点使用节点配置中的 `approverIds` 回退展示。
- 抄送人来自独立抄送数据，不计入审批节点和审批完成比例。
- 历史单据若没有企业微信流程快照，则回退到本地节点与任务；两者均不存在时显示统一空态。

## 验证要求

- 单元测试覆盖多金额字段、待审批状态过滤、部门聚合和未分配部门。
- TypeScript 类型检查和生产构建通过。
- 桌面端验证部门卡片每行最多四张，金额和笔数可快速扫描。
- 窄屏验证卡片换行、长部门名称和大额数字不与相邻内容重叠。
- 企业微信单据存在本地占位节点时，详情仍展示企业微信真实审批人、状态和操作时间。
- 本地单据展示任务审批人，尚未流转到的节点仍能展示配置审批人。
